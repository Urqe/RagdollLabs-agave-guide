# Mexico states geometry

`mexico-states.svg` is generated by `scripts/build-map.py` from the
[Natural Earth](https://www.naturalearthdata.com/) 10m Admin 1 — States,
Provinces dataset (public domain, no attribution required), Mexico subset.

## Why this source

The previous Release 1 map was composited from per-state SVGs
([midir99/mexico-states-in-svg](https://github.com/midir99/mexico-states-in-svg),
MIT License, drawn from INEGI maps). That source drew each state in its
own normalized coordinate system (every state scaled to fill its own
square canvas), so the composite could not form a geographically correct
map of Mexico. It was replaced in Release 2 with true Natural Earth
admin-1 boundaries.

## Transformation

`scripts/build-map.py` reads the Natural Earth GeoJSON (from a local
path or its documented raw URL), keeps the 32 Mexican state features
(an unnamed small island feature, Isla Mujeres, is excluded), and writes
one `<path data-state="…">` per state with a simple equirectangular
projection using a cosine mid-latitude scale factor (~cos 23.5°), so
states are positioned correctly relative to each other. No boundary
simplification beyond Natural Earth's own 10m detail and coordinate
rounding to 2 decimals.

- Source snapshot: `ne_10m_admin_1_states_provinces.geojson` from
  [nvkelso/natural-earth-vector](https://github.com/nvkelso/natural-earth-vector)
  (retrieved 2026-10-20)
- License: public domain (Natural Earth)
- Transformation date: 2026-10-20
- Tool: `scripts/build-map.py` (Python 3 standard library only)
- Reproduce: `python3 scripts/build-map.py [path/to/ne_10m_admin_1_states_provinces.geojson]`

## Selection semantics

All 32 states are rendered for geographic context. Only states that
have style profiles in the app are interactive (selectable on the map,
listed in the state list); the app applies this at runtime via the
`is-selectable` / `is-inert` classes in `assets/js/map.js`.
